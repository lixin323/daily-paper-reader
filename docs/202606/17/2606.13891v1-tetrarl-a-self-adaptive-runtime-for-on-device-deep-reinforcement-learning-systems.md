## 摘要
自主机器人系统，包括自动驾驶汽车、无人机和移动机器人，越来越依赖设备上的深度强化学习（DRL）来适应动态环境。与基于云的解决方案不同，嵌入式DRL必须在资源受限的硬件上直接执行训练和推理，同时保持及时的决策。这产生了一个基本挑战：平衡四个紧密耦合的目标——实时性能、任务奖励、内存利用率和能耗。独立优化这些目标通常会导致次优行为，而传统的多目标方法可能违反资源约束并损害可靠性。本文介绍了TetraRL，一种面向四目标设备上DRL的自适应运行时框架。TetraRL将嵌入式DRL表述为一个关于实时、奖励、内存和储备（能耗）目标的统一优化问题，并采用偏好条件强化学习控制器来动态导航由此产生的权衡空间。该框架集成了统一的资源管理抽象、硬件感知的DVFS控制以及用于鲁棒约束执行的运行时覆盖层。我们在NVIDIA Jetson AGX Orin和Orin Nano平台上实现了TetraRL，并在多种DRL环境中进行评估。结果表明，TetraRL有效平衡了所有四个目标，在变化的运行时偏好下实现了有竞争力的权衡，并且开销可忽略。此外，单个训练好的策略可以支持运行时切换的优化目标，为资源感知和自适应的设备上DRL提供了实用基础。

## Abstract
Autonomous robotic systems, including autonomous vehicles, drones, and mobile robots, increasingly rely on on-device Deep Reinforcement Learning (DRL) to adapt to dynamic environments. Unlike cloud-based solutions, embedded DRL must perform training and inference directly on resource-constrained hardware while maintaining timely decision-making. This creates a fundamental challenge: balancing four tightly coupled objectives, real-time performance, task reward, memory utilization, and energy consumption. Optimizing these objectives independently often leads to suboptimal behavior, while conventional multi-objective methods may violate resource constraints and compromise reliability.   This paper presents TetraRL, a self-adaptive runtime framework for tetra-objective on-device DRL. TetraRL formulates embedded DRL as a unified optimization problem over real-time, reward, RAM, and reserve (energy) objectives, and employs a preference-conditioned reinforcement learning controller to dynamically navigate the resulting trade-off space. The framework integrates a unified resource-management abstraction, hardware-aware DVFS control, and a runtime Override Layer for robust constraint enforcement. We implement TetraRL on NVIDIA Jetson AGX Orin and Orin Nano platforms and evaluate it across diverse DRL environments. Results show that TetraRL effectively balances all four objectives, achieves competitive trade-offs under varying runtime preferences, and incurs negligible overhead. Moreover, a single trained policy can support runtime-switchable optimization goals, providing a practical foundation for resource-aware and self-adaptive on-device DRL.

## 2. 论文提出的方法论：核心思想、关键技术细节

### 2.1 核心思想
- 将设备上DRL问题建模为一个**约束多目标马尔可夫决策过程（MOMDP）**，状态空间包含硬件遥测、算法状态和偏好向量 ω，动作空间为系统动作（调整算法资源旋钮和DVFS频率）。
- 使用**偏好条件PPO**作为运行时控制器，将用户偏好嵌入策略输入，单个策略可覆盖整个R4偏好空间，无需为每个偏好单独训练。
- 框架由四个组件构成：**偏好平面**（提供当前ω）、**资源管理器**（采集遥测并执行动作）、**RL仲裁器**（偏好条件策略）、**硬件覆盖层**（强制执行安全约束）。

### 2.2 关键技术细节
- **运行时状态**：`zt = [ht, qt, f_cpu, f_gpu, ω]`，包含延迟、内存、功率、温度等。
- **动作空间**：`asys = (Δu, Δf_cpu, Δf_gpu)`，u是算法特定资源旋钮（如批量大小、回放容量、rollout长度）。
- **4-D奖励向量**：`rt = [ -cL(Lt), r_env, -cM(Mt), -cE(Et) ]`，经Z-score归一化后用权重ω标量化。
- **统一资源原语抽象**：将不同DRL算法映射到四个原语——样本、更新、存储、同步，使同一控制器兼容离策略（DQN、DDQN、C51）和在策略（A2C、PPO）算法。
- **硬件覆盖层**：在RL仲裁器输出后检查动作是否违反硬件安全阈值，若违反则替换为保守恢复动作，减少违规频率和幅度（非零违规保证）。
- **超体积（HV）**作为主要多目标质量指标。
- **奖励封顶提前退出钩子**：一旦单episode达到环境奖励上限，立即停止训练，避免浪费计算和能量。

### 2.3 算法流程（文字说明）
1. 初始化基础DRL任务策略和TetraRL仲裁器（PPO）。
2. 每个episode开始时采样或接收偏好向量ω。
3. 按控制块循环（每N_block步进行一次系统动作）：
   - 资源管理器采集遥测，构造状态zt。
   - 仲裁器采样系统动作，覆盖层投影为安全动作。
   - 资源管理器应用动作（调整算法旋钮和DVFS）。
   - 执行N_block个环境步骤，更新基础DRL策略，测量延迟、内存、能量并计算系统奖励。
   - 存储转移用于仲裁器更新。
4. 使用PPO更新仲裁器（基于标量化系统奖励）。
5. 定期评估：用固定偏好锚点扫描恢复Pareto前沿，记录HV、前沿基数等。

## 6. 论文的主要结论与发现

1. **统一四维优化有效**：TetraRL在所有测试环境中一致地平衡延迟、奖励、内存和能耗，在资源受限平台上显著优于R3/DuoJoule等二维方法。
2. **提前退出带来巨大时间节省**：在CartPole-v0上，TetraRL因奖励封顶提前退出，将DQN运行时间从193秒降至19.7秒（10倍），对Breakout AGX则从6625秒降至3310秒（2倍）。
3. **预算匹配协议下开销极低**：在固定样本预算下（CartPole-v1），TetraRL的延迟接近R3（差异<1%），纯框架步时开销仅0.078ms（4.4%）。
4. **单策略支持运行时切换偏好**：通过偏好条件输入，训练好的策略可在不重新训练的情况下，在不同优化目标间切换（如从高奖励模式切换到低能耗模式）。
5. **跨平台鲁棒性**：在AGX和Nano上保持一致的性能排序，而MAX-A和R3在Nano上出现显著退化或OOM。
6. **Pareto前沿质量**：与专用MORL基线DVFS-DRL-Multitask相比，TetraRL在3/4个平台-环境组合上取得相同或更高的超体积。

## 7. 优点

- **全面性**：首次提出设备上DRL的R4四维联合优化框架，填补了现有方法只覆盖部分维度的空白。
- **通用性**：统一资源原语抽象使其兼容离策略和在策略DRL算法（DQN/DDQN/C51/A2C/PPO），而R3/DuoJoule仅支持价值型。
- **低开销**：纯框架控制逻辑仅0.078ms/步（4.4%），<1%内存增量，适合资源受限部署。
- **自适应性**：偏好条件策略允许在运行时动态切换优化目标，无需重新训练或手动配置多个控制器。
- **硬件意识**：集成DVFS控制器并测量实际转换延迟（GPU平均3.4ms），采用超级块决策粒度摊薄开销；硬件覆盖层作为安全后盾。
- **实验扎实**：在两个Jetson平台、多种环境和算法下进行广泛评估，包括详细的组件开销分析和MORL基准对比。

## 8. 不足与局限

- **硬件覆盖层非正式保证**：由于遥感和DVFS延迟，覆盖层不能保证零约束违规，论文中承认仅作为“减少违规频率和幅度”的机制。
- **单种子Breakout实验**：Atari Breakout结果仅基于1个随机种子，缺乏统计可靠性（作者说明因计算开销大，这是该领域的常见做法，但仍属局限）。
- **缺乏真实机器人部署**：所有实验在模拟环境（Gymnasium）中运行，未在真实自主机器人（如无人机、移动机器人）上验证。
- **多目标对比不够全面**：4-D Pareto对比仅与DVFS-DRL-Multitask比较（且该基线在AGX dag上统计不显著），未与更现代MORL方法（如PD-MORL、PCN）在硬件上对比（作者提到PD-MORL/PCN的计算需求和代码不兼容问题）。
- **仅两个Jetson平台**：结果可推广性限于NVIDIA Jetson系列（统一内存架构），未覆盖其他边缘硬件（如树莓派、Intel计算棒、TPU等）。
- **仅四个目标**：未考虑其他重要维度如温度、通信带宽、安全约束等。随着需求增加，框架扩展性待验证。
