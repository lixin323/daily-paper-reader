## 摘要
视觉-语言-动作（VLA）模型在机器人操作方面展现出巨大潜力，但在边缘硬件上的实时部署仍具挑战。本文中，我们指出VLM的视觉和上下文token是部署延迟的主要来源：对于以GEMM为主的投影算子，当模型维度固定时，计算量随输入token数量线性增长。基于此观察，我们提出RhinoVLA，一种面向部署的VLA模型，与慧犀R1边缘SoC协同设计。RhinoVLA采用token高效的Qwen3-VL骨干网络和连续动作专家模块，在保留预训练多模态能力的同时减轻了VLM侧的token和计算负担。为支持跨机器人学习，RhinoVLA进一步引入统一接口，结合视图注册表、72维物理状态-动作槽空间和机器人实例LoRA，使得异构机器人观测和动作模式能够在共享策略下对齐。在部署方面，RhinoVLA通过硬件感知编译、混合精度执行和并行视觉编码进行优化。实验表明，RhinoVLA在相似参数量下达到与π0.5相当的下游性能，同时在慧犀R1上实现11.69 Hz端到端推理，满足10 Hz实时闭环控制目标。项目将开源在https://github.com/HuixiAI/RhinoVLA。

## Abstract
Vision-Language-Action (VLA) models have shown strong potential for robotic manipulation, but real-time deployment on edge hardware remains challenging. In this work, we identify VLM visual and context tokens as a major source of deployment latency: for GEMM-dominated projection operators, computation grows linearly with the number of input tokens when model dimensions are fixed. Motivated by this observation, we propose RhinoVLA, a deployment-oriented VLA model co-designed with the Huixi R1 edge SoC. RhinoVLA adopts a token-efficient Qwen3-VL backbone and a continuous Action Expert, reducing the VLM-side token and computation burden while preserving pretrained multimodal capability. To support cross-robot learning, RhinoVLA further introduces a unified interface that combines View Registry, 72D physical state-action slot space, and robotinstance LoRA, allowing heterogeneous robot observations and action schemas to be aligned under a shared policy. On the deployment side, RhinoVLA is optimized through hardware-aware compilation, mixed-precision execution, and parallel visual encoding. Experiments show that RhinoVLA achieves downstream performance comparable to π0.5 at a similar parameter scale, while reaching 11.69 Hz end-to-end inference on Huixi R1, meeting the 10 Hz real-time closedloop control target. The project will be open-sourced at https://github.com/HuixiAI/RhinoVLA.

## 1. 论文的核心问题与整体含义（研究动机和背景）
- **研究动机**：视觉-语言-动作（Vision-Language-Action, VLA）模型在机器人操控中展现出强大的潜力，但在边缘硬件（如机器人载板）上实现实时闭环控制非常困难。现有VLA系统通常使用预训练的大视觉语言模型（VLM），其长多模态上下文和迭代动作生成模块带来巨大的计算和内存开销，导致端到端推理延迟过高，难以满足10 Hz的实时控制需求。
- **关键瓶颈**：通过性能分析发现，VLM中MLP投影算子（gate_proj, up_proj, down_proj）是延迟的主要来源（占VLM延迟约74.7%）。这些算子是GEMM运算，其计算量与输入token数量线性相关。因此，减少VLM侧的视觉和上下文token数成为提升部署速度的核心杠杆。
- **整体目标**：设计一个算法-系统协同优化的VLA模型，既能保持强大的多模态感知和动作生成能力，又能在低功耗边缘芯片上达到实时推理速度，同时支持异构机器人数据的统一训练。

## 2. 论文提出的方法论：核心思想、关键技术细节
**核心思想**：采用token高效的VLM骨干（Qwen3-VL）从源头降低计算量；设计统一跨机器人接口（View Registry、72D物理槽空间、机器人实例LoRA）对齐异构数据；通过硬件感知编译、混合精度、并行编码等系统优化实现边缘实时推理。

**关键技术细节**：
- **VLM骨干选择**：采用Qwen3-VL-2B，在256×256图像设置下每张图像仅产生64个合并视觉token，而π0.5使用的PaliGemma-224产生256个token，减负4倍。
- **Action Expert**：18层Transformer，参数量0.40B（与π0.5的0.43B相当），利用Qwen3-VL最后18层KV缓存条件，预测72维槽空间的流速度（flow matching）。
- **统一跨机器人接口**：
    - **View Registry**：为每张图像添加显式标签，如`[head|rgb]`、`[left_wrist|rgb]`，解耦相机身份与数据集顺序。
    - **72D物理状态-动作槽空间**：每个槽具有固定的物理含义（如D0-D6左臂关节角、D14-D15平行夹爪开合比、D58-D60基座速度等），并配二进制掩码标示有效维度，避免错位监督。
    - **机器人实例LoRA**：在Action Expert的每个FFN层插入低秩适配器，只对当前机器人实例生效，学习残差特定行为，共享主网络。
- **训练策略**：
    - 预训练：Qwen3-VL骨干冻结，训练VLM LoRA、共享Action Expert和机器人实例LoRA。采用掩码流匹配损失，仅对有效动作槽计算梯度。
    - 后训练/真实机器人迁移：冻结VLM及大部分Action Expert，仅更新目标机器人的实例LoRA。
- **部署优化（Huixi R1 SoC）**：
    - 编译优化：FlashAttention风格的tiling、算子融合（归一化+投影+激活+残差）、细粒度任务调度。
    - 混合精度：W8A16（INT8权重+FP16激活），并定制融合GEMM内核，规避反量化开销。
    - 并行视觉编码：三视角图像批处理，延迟从34.52 ms降至24.31 ms。
